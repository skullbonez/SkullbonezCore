## Fix Order

1. Preserve the existing guardrail: run `python tools/check_runtime_boundaries.py --repo .` before a source slice so the baseline is known.
2. Pick one owner bucket, not the whole 579-hit surface. Good first buckets are future render-resource context, future runtime settings context, or Phase 3 physics compatibility.
3. Replace reads of `Cfg()`, `Gfx()`, `GfxRayTracing()`, `CreateShaderFromActiveAssets()`, `WorkerPool::Instance()`, `Profiler::Instance()`, and process globals with explicit borrowed context objects at the owning boundary.
4. Update or remove the corresponding allowlist/count in `tools/check_runtime_boundaries.py` in the same slice, so the removed row cannot return silently.
5. Rerun the smallest matching validation gate for the touched source area before commit/PR handoff.

## Owner Buckets

- `Future render-resource context`: renderer/helper/text/world rows; usually requires DX12 renderer validation and sometimes perf validation.
- `Future runtime settings context`: camera/input/frame/runtime rows; usually requires fast/full validation depending on touched lifecycle.
- `Phase 3 physics compatibility`: physics config/worker rows; requires physics validation and careful determinism review.
- `DiagnosticsRuntime / profiler facade`: diagnostics rows; preserve observability while reducing direct profiler/backend globals.
- `Run composition root`: bootstrap and top-level backend borrow rows; keep only where process lifetime is intentionally wired.
